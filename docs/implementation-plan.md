# План реализации

## Цель

Сделать Epson L3250 доступным для устройств Apple по AirPrint через Ubuntu-сервер в Docker. Цепочка печати:

`iPhone / iPad → AirPrint (IPP + mDNS) → CUPS на сервере → IPP → Epson L3250`

## Исходные данные

- Принтер: Epson L3250.
- Текущий IP принтера: `192.168.1.207`.
- Платформа шлюза: Ubuntu с Docker и Docker Compose.
- iPhone и сервер находятся в одной домашней локальной сети.

IP принтера будет параметром окружения, а не значением в исходном коде. До развёртывания следует создать DHCP-резервацию для принтера в роутере.

## Границы проекта

Входит:

- печать с iOS/iPadOS через AirPrint;
- сетевое подключение к принтеру по IPP;
- сохранение очереди и конфигурации CUPS между обновлениями;
- диагностические команды и документация эксплуатации.

Не входит на первом этапе:

- доступ к печати из интернета;
- сканирование с iPhone;
- поддержка нескольких принтеров;
- автоматическая настройка роутера.

## Этапы

### 0. Предпроверки окружения

**Результат:** подтверждены сеть, доступность оборудования и зависимости на сервере.

1. Проверить версии Ubuntu, Docker Engine и Docker Compose.
2. Убедиться, что сервер видит `192.168.1.207` и IPP-порт принтера.
3. Зафиксировать подсеть и интерфейс домашней сети сервера.
4. Создать DHCP-резервацию IP для Epson в роутере.
5. Проверить, что порт `631` не занят локальным CUPS/другим сервисом, а Avahi не работает на хосте либо согласован с контейнерной схемой.

**Критерий готовности:** сервер стабильно достигает принтера; выбран безопасный способ исключить конфликт с хостовыми CUPS и Avahi.

### 1. Каркас репозитория и параметры

**Результат:** воспроизводимый Compose-проект без секретов в Git.

1. Добавить `compose.yaml`, `.env.example`, `.gitignore` и `Makefile`.
2. Внести настраиваемые параметры: IP/URI принтера, имя очереди, отображаемое имя AirPrint, локальная подсеть и часовой пояс.
3. Описать постоянные Docker volumes для состояния CUPS и журналов (если потребуется).
4. Настроить `restart: unless-stopped`.

**Критерий готовности:** проект запускается из чистого клона после копирования `.env.example` в `.env`.

### 2. Контейнер CUPS и очередь Epson

**Результат:** CUPS печатает тестовую страницу на Epson по IPP.

1. Создать образ CUPS с `cups` и `printer-driver-escpr`.
2. Подготовить безопасный `cupsd.conf`: доступ к печати только из локальной сети; административный интерфейс — только с сервера либо из явно разрешённой подсети.
3. Создать идемпотентный скрипт инициализации очереди `Epson-L3250` с URI из `.env`.
4. Выбрать идентификатор драйвера из установленного ESC/P-R и зафиксировать его в настройке.
5. Сохранить конфигурацию CUPS в volume.

**Критерий готовности:** `lpstat` показывает доступную очередь, а тестовая страница успешно распечатывается.

### 3. Публикация AirPrint через Avahi

**Результат:** iPhone видит очередь CUPS как AirPrint-принтер.

1. Создать контейнер Avahi и его конфигурацию.
2. Использовать `network_mode: host`, чтобы mDNS-анонсы попадали в домашнюю сеть.
3. Добавить сервис-описание AirPrint для очереди CUPS: `_ipp._tcp` и необходимые TXT-записи.
4. Указать правильные возможности печати (PDF/JPEG, цвет, размеры бумаги) по фактическим возможностям очереди CUPS.
5. Проверить публикацию с Linux-инструментами mDNS и с iPhone.

**Критерий готовности:** в системном диалоге «Печать» iOS появляется понятное имя принтера без установки Epson iPrint.

### 4. Операционные команды и наблюдаемость

**Результат:** сервис удобно запускать, проверять и диагностировать.

1. Добавить команды `make up`, `make down`, `make logs`, `make status`, `make test`.
2. Реализовать `scripts/status.sh`: доступность принтера, состояние контейнеров и очереди CUPS.
3. Реализовать `scripts/test-print.sh`: контролируемая отправка тестовой страницы.
4. Сделать установочный скрипт очереди безопасным для повторного запуска.

**Критерий готовности:** типовые проверки выполняются одной командой и дают понятный результат/ошибку.

### 5. Приёмочное тестирование и эксплуатационная документация

**Результат:** решение подтверждено реальной печатью и подготовлено к сопровождению.

1. Протестировать PDF из «Файлов» и изображение из «Фото» на iPhone.
2. Проверить цветную и чёрно-белую печать, а также формат A4.
3. Перезапустить контейнеры и сервер; убедиться, что очередь и AirPrint-анонс восстанавливаются.
4. Документировать обновление образов, резервное копирование volumes и сценарии диагностики.

**Критерий готовности:** после перезагрузки Ubuntu iPhone вновь находит принтер, а печать проходит без ручной настройки.

## Порядок выполнения

Работа выполняется последовательно: этапы 0 → 1 → 2 → 3 → 4 → 5. Следующий этап начинается только после выполнения критерия готовности предыдущего.

## Риски и меры

| Риск | Проявление | Мера |
| --- | --- | --- |
| IP принтера изменился | Очередь недоступна | DHCP-резервация и параметр `PRINTER_URI` в `.env` |
| mDNS не виден из контейнера | iPhone не находит принтер | `network_mode: host`, проверка VLAN/изоляции Wi-Fi |
| Конфликт с CUPS/Avahi хоста | Заняты порты или двойные анонсы | Предпроверка и явное решение на этапе 0 |
| Неверный драйвер | Задания зависают или печать искажена | Проверка ESC/P-R и тестовая страница до настройки AirPrint |
| Устройства в разных сегментах сети | Обнаружение не работает | Использовать одну LAN либо отдельно настраивать mDNS reflector |
